# Splint Validation Debt

This ledger separates evidence that automation can provide from evidence that
requires real players, physical Telegram devices, or market behavior. Debt does
not stop reversible product work unless the entry explicitly says so.

## VD-CORE-FEEL-001

Hypothesis: the Recovery core slice produces a satisfying player-authored reveal
before assisted throughput appears.

Status: OPEN — provisional baseline accepted for continued Phase 2 work.

Agent evidence: automated Phase 0/1 and Phase 2 tests, browser route checks,
Canvas/application-state checks, and preserved input/reload guardrails.

Human evidence missing: 8–12 observed players on real Telegram Android/iOS
devices, including treatment/control comparison and verbal authorship feedback.

Risk: MEDIUM. A machine-passing slice can still feel flat or interruptive.

Blocks: public claim that core enjoyment is proven; final UX lock.

Does NOT block: reversible Phase 2 prototypes, simulator work, and agent review.

Provisional decision: keep the player-authored reveal contract as the baseline;
do not restore meta noise or broad Special Cells while evidence is collected.

## VD-PHASE2-SPECIAL-001

Hypothesis: one rare positive spectacle plus passive Artifact discovery improves
anticipation without making the player a passenger.

Status: OPEN — candidate selection pending blinded agent comparison.

Agent evidence: audit verdicts identify Spark/Bomb as redesign candidates,
Artifact as the only plausible discovery event, and Fuse/Hazard/Choice as
cut/merge candidates; Phase 2 treatment currently gates Spark + Artifact.

Human evidence missing: want-again, agency, calmness, and continuation scores
for the selected event versus core-only control.

Risk: MEDIUM-HIGH if an event steals authorship or adds modal cost.

Blocks: final Special Cells lock and broad cohort rollout.

Does NOT block: bounded prototypes, deterministic simulations, and visual review.

Provisional decision: test at most one positive event and one Artifact path;
keep Fuse, Hazard, and Choice disabled in the experimental product path.

## VD-TELEGRAM-WEBVIEW-001

Hypothesis: the Phase 2 slice preserves input, reduced-motion, sound-off,
resume, and safe-area behavior in Telegram WebView.

Status: OPEN.

Agent evidence: Chromium/mobile emulation, automated reload/offline contracts,
reduced-motion branches, and API health checks.

Human evidence missing: physical Telegram Android and iOS WebView sessions,
including background/resume and haptics/audio-off checks.

Risk: MEDIUM.

Blocks: production Telegram claim and release sign-off.

Does NOT block: local Phase 2/3 iteration while contracts remain bounded.

Provisional decision: preserve current performance guardrails and record device
validation as release debt rather than inventing more UI work.

## VD-PIXELIZATION-001

Hypothesis: a paintability-aware pixelization recommendation improves first
session quality without reducing artistic appeal.

Status: OPEN — R&D stream.

Agent evidence: existing Recovery benchmark and deterministic converter parity
checks; new candidate evidence will be appended by the pixelization stream.

Human evidence missing: blinded artistic preference and creator acceptance.

Risk: MEDIUM.

Blocks: final automatic style recommendation and broad creator rollout.

Does NOT block: benchmark work or using the current safe preset as default.

Provisional decision: keep the current safe preset until a candidate wins on
paintability, preview/final parity, and performance together.
